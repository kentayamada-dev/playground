現在のブランチの変更内容で PR を作成する。起動後は途中で確認を挟まず最後まで実行してよい。例外は次の 2 つ。

- 前提条件を満たさない場合は、PR を作成せずに状況をユーザーへ伝えて終了する
- 既存の PR のタイトルや本文を書き換える場合は、事前に許可を得る（「更新」の手順 3）

指示がないのにコミットや push を始めてはいけない。

## 前提条件の確認

スキル起動時点の状態は次のとおり。

<!-- textlint-disable ja-technical-writing/no-exclamation-question-mark -->

- 現在のブランチ: !`git branch --show-current`
- `git status -sb` の出力:

<!-- textlint-enable ja-technical-writing/no-exclamation-question-mark -->

```!
git status -sb
```

1. 現在のブランチが `main` なら、作業ブランチを切るよう伝えて終了する
2. `git status -sb` の先頭行で upstream の有無と `ahead` を確認する。upstream が無い、または `ahead` があれば、push が必要なことを伝えて終了する
3. `git status -sb` の 2 行目以降に出力があれば、未コミットの変更は PR に含まれないことを伝えて終了する
4. `gh pr view --json number,url` で現在のブランチの PR を確認する。存在すれば新規作成せず「更新」に進む

## 手順

1. `git fetch origin main` のあと、`git log origin/main..HEAD --oneline` と `git diff origin/main...HEAD` を通しで読む
   - デバッグ用のログ、コメントアウトした不要コード、意図しないファイルの混入を確認する
2. `.github/pull_request_template.md` の各セクションを、HTML コメント（書き方のガイド）に従って埋めて本文を作る
   - HTML コメントは削除せずそのまま残す
3. 本文を一時ファイルに書き、`gh pr create --base main --title "<タイトル>" --body-file <ファイル>` で作成する
   - タイトルは CONTRIBUTING.md の規約に従う
4. 作成した PR の URL をユーザーに伝える

## 更新

PR の本文は、そのブランチの最新のコードを説明していなければならない。次のときに更新する。

- 既存の PR がある状態でこのスキルを起動したとき
- PR があるブランチに push した直後。push を指示された作業の続きとして、改めて指示を待たずに手順 2 の照合まで進め、本文が古いまま次の作業に進まない

手順は次のとおり。

1. `gh pr diff <番号>` で PR の差分を読み直す。前回読んだときの記憶で済ませない
2. `gh pr view <番号> --json title,body,commits` で現在のタイトル・本文・コミット一覧を取得し、セクションごとに差分と照合する
   - タイトル: 変更の主眼が変わっていないか
   - 背景/なぜ: 方針転換があれば理由を書き換える
   - 何をしたか: 追加・削除・作り直した変更が反映されているか
   - 確認方法: コマンドの出力や CI の結果は、最新のコミットに対して実行したものだけを残す。
     差分が変わったのに前回の結果を残さない。再実行していない項目はチェックを外す
   - レビューで見てほしい点: 解消した論点は消し、新たに迷った箇所を足す
3. 食い違いがあれば、変更するセクションと変更後の内容を示して `AskUserQuestion` で許可を得てから、
   `gh pr edit <番号> --title "<タイトル>"` や `gh pr edit <番号> --body-file <ファイル>` で修正する。
   無ければ更新せず、照合した範囲と結果をユーザーに報告する
4. 古くなった記述は「追記」で残さず消す。本文は変更の履歴ではなく、現在の状態の説明にする
